# How three.js websites are built today, and what applies to "Our Memory in Taipei"

Researched 2026-09-21. Every claim carries a URL. Terms are glossed on first use. "UMD" means the old single-file build of three.js that you load with a plain `<script>` tag; "ES modules" means the newer `import`-based files that need either a web server or a bundler.

Pattern summary: nearly every narrative site uses one of three shapes. (a) Camera on a curve, scroll sets progress. (b) Scroll scrubs an animation timeline (GSAP or Theatre.js). (c) Fixed canvas with HTML sections scrolling over it. Your project is shape (a) with (c)'s text overlay, which is the mainstream choice.

## 2. The standard toolchain in 2025–2026

**Vite.** A dev server plus bundler: it serves your files during development and packs them into optimised files for release ([vite.dev](https://vite.dev/guide/why)). Cost: a Node.js install, a `package.json`, and a build step before every deploy. It breaks your "no build" rule.

**Vanilla three.js.** Plain three.js with no wrapper. Since r148 the add-ons (loaders, post-processing passes, `BufferGeometryUtils`) exist only as ES modules under `examples/jsm` ([forum announcement](https://discourse.threejs.org/t/the-examples-js-directory-will-be-removed-with-r148/45349)); the single-file UMD build was deprecated in r150 and removed in r161 ([PR #25435](https://github.com/mrdoob/three.js/pull/25435), [forum](https://discourse.threejs.org/t/umd-version-of-three-js-v-161/60912)). Your r149 UMD file is therefore the last era where `<script src="three.min.js">` works, and it ships with no add-ons. Cost of staying: you hand-copy any add-on you want.

**React Three Fiber (R3F) and drei.** A React renderer for three.js: you write the scene as components. The docs claim no overhead and better scheduling at scale ([r3f docs](https://r3f.docs.pmnd.rs/getting-started/introduction)). drei is its helper library; its `ScrollControls` gives pages, damping and a `useScroll` hook for scroll-driven scenes ([drei docs](https://drei.docs.pmnd.rs/controls/scroll-controls)). Cost: React, a bundler, and a new mental model.

**Threlte** is the same idea for Svelte ([threlte.xyz](https://threlte.xyz/)); **TresJS** for Vue ([tresjs.org](https://tresjs.org/)). Same cost shape as R3F.

**GSAP ScrollTrigger.** Ties any animation to the scrollbar; `scrub: 1` makes the animation take one second to catch up to the scroll position, `pin` freezes a section in place ([docs](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)). GSAP is now free for commercial use ([pricing](https://gsap.com/pricing/)). Ships as UMD on a CDN, so it could be vendored as a local file. Cost: one script file; it breaks your "no framework" spirit only if you count a library.

**Lenis.** A smooth-scroll library under 4 KB that wraps native scroll so anchors and sticky elements keep working; default `lerp` 0.1, honours `prefers-reduced-motion`; has a UMD build ([README](https://github.com/darkroomengineering/lenis/blob/main/README.md)). Cost: one script file plus a `raf` call per frame.

**Post-processing.** three's own `EffectComposer` chains full-screen passes (bloom, outline, pixelation) ([OutlinePass example](https://threejs.org/examples/webgl_postprocessing_outline.html)). The `postprocessing` library by pmndrs merges effects into one pass for speed and ships SSAO, outline, pixelation, bloom, and more ([repo](https://github.com/pmndrs/postprocessing)). Both are ES modules. Cost: needs modules, so needs a server.

**Theatre.js.** A visual keyframe editor in the browser; you scrub a timeline, then export the keyframes to JSON for production ([three.js guide](https://www.theatrejs.com/docs/latest/getting-started/with-three-js)). Requires a bundler. Cost: Vite plus learning the studio; big win only if you have many hand-timed camera moves.

**glTF plus Draco, Meshopt, KTX2.** glTF is the standard 3D model file. Draco and Meshopt shrink geometry; KTX2 with Basis keeps textures compressed on the GPU, typically 4 to 8× less video memory ([glTF Transform](https://gltf-transform.dev/), [three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)). The **Blender to glTF** pipeline is: model in Blender, export `.glb`, run `gltf-transform` to compress, load with `GLTFLoader` plus the matching decoder. Cost: model files (breaks your rule), decoders that must be fetched (breaks no-network unless vendored), and Blender skills.

## 3. How stylised looks are done in three.js

| Look | How | Where to see it | Works in r149 UMD from file://? |
|---|---|---|---|
| Toon / cel | `MeshToonMaterial` with a `gradientMap`: a tiny 3 to 5 pixel texture that quantises light into bands; must use `NearestFilter` ([docs](https://threejs.org/docs/pages/MeshToonMaterial.html)) | [webgl_materials_toon](https://threejs.org/examples/webgl_materials_toon.html) | Yes, the gradient can be a `DataTexture` or canvas texture |
| Outlines, inverted hull | Draw each mesh a second time, slightly scaled, black, `side: BackSide` ([Observable example](https://observablehq.com/@vicapow/three-js-example-of-a-toon-material-with-outline/2)) | same | Yes, core only |
| Outlines, post-process | `OutlinePass` (edge detection on selected objects) or `OutlineEffect` (automatic inverted hull for the whole scene) | [webgl_postprocessing_outline](https://threejs.org/examples/webgl_postprocessing_outline.html) | No, add-on modules |
| Clay / diorama | Matcap materials (a sphere image that fakes lighting, [MeshMatcapMaterial](https://threejs.org/docs/#api/en/materials/MeshMatcapMaterial)), soft ambient occlusion such as SAO or N8AO ([SAO example](https://threejs.org/examples/webgl_postprocessing_sao.html), [N8AO](https://github.com/N8python/n8ao)), area lights | Bruno Simon's palette-texture trick is the no-AO version | Matcap yes if drawn on a canvas; AO no (add-on, N8AO wants r161+) |
| Pixel / PS1 | `RenderPixelatedPass` for chunky pixels with optional edge lines ([example](https://threejs.org/examples/webgl_postprocessing_pixel.html)); for full PS1: vertex snapping, affine texture wobble, 15-bit dither, `NearestFilter` ([Roman Liutikov](https://romanliutikov.com/blog/ps1-style-graphics-in-threejs), [Codrops jitter](https://tympanus.net/codrops/2024/09/03/how-to-create-a-ps1-inspired-jitter-shader-with-react-three-fiber/)) | | Pass no; render to a small render target and upscale with `NearestFilter` yes (core) |
| Hand-drawn / print | Sobel edges on colour plus normal buffers, then noise-distort the sample position for wobbly lines ([Codrops pencil](https://tympanus.net/codrops/2022/11/29/sketchy-pencil-effect-with-three-js-post-processing/), [repo](https://github.com/mayacoda/pencil-lines)); cross-hatching by light intensity ([clicktorelease](https://www.clicktorelease.com/code/cross-hatching/), [spite/sketch](https://spite.github.io/sketch/)) | | Post-process no; a hatching `ShaderMaterial` per object yes |

## 4. Performance and scroll patterns for a 460-unit street

- **Draw calls are the usual limiter.** The manual merges ~19,000 boxes into one geometry to remove 18,999 draw operations, using vertex colours to keep per-box colour ([Optimize Lots of Objects](https://threejs.org/manual/en/optimize-lots-of-objects.html)). `mergeGeometries` is an add-on; `InstancedMesh` is core and draws many copies of one geometry in one call ([docs](https://threejs.org/docs/pages/InstancedMesh.html)).
- **Frustum culling** (skipping objects outside the camera's view) is automatic per object, but an `InstancedMesh` is culled as one whole bounding sphere, not per instance ([docs](https://threejs.org/docs/pages/InstancedMesh.html)). For a long street, keep instanced groups per chapter so a whole chapter can drop out.
- **LOD** swaps a mesh for a simpler one past a distance, via `addLevel(mesh, distance)` ([docs](https://threejs.org/docs/pages/LOD.html)). A tight `camera.far` plus fog does most of this for free.
- **Texture atlases**: one canvas holding all word textures means one material instead of dozens. Bruno Simon used a palette texture for colour variation without per-vertex colours ([case study](https://www.awwwards.com/brunos-portfolio-case-study.html)).
- **Pixel ratio cap**: `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`; both Codrops scroll tutorials do this ([2022](https://tympanus.net/codrops/2022/01/05/crafting-scroll-based-animations-in-three-js/), [2025](https://tympanus.net/codrops/2025/11/19/how-to-build-cinematic-3d-scroll-experiences-with-gsap/)). Antialias (MSAA) multiplies fragment work; consider off on low-power devices.
- **Render on demand**: only render when something changed ([manual](https://threejs.org/manual/en/rendering-on-demand.html)). Only applies if the girl stops running when scroll is idle.
- **Camera on a Catmull-Rom curve**: `curve.getPointAt(t)` for position, look at `getPointAt(t + small)` so the camera faces along the road; DEPT uses +0.06 and a second spline for the gaze; fewer control points means less jitter ([DEPT](https://www.dept.global/en-us/insight/coding-a-cinematic-camera-path/)).
- **Scroll smoothing**: keep a raw `targetT` from scroll and a smoothed `t` that eases toward it each frame ([Codrops Curve Gallery](https://tympanus.net/codrops/2026/07/07/building-a-scroll-driven-3d-gallery-using-a-blender-camera-path-with-three-js-and-gsap/)); use a delta-time lerp so speed is frame-rate independent ([Codrops 2022](https://tympanus.net/codrops/2022/01/05/crafting-scroll-based-animations-in-three-js/)).
- **Background tabs**: Chrome stops `requestAnimationFrame` entirely when a tab is hidden, but an unfocused yet visible window keeps rendering ([Chrome blog](https://developer.chrome.com/blog/background_tabs)). Clamp your delta time so the girl does not teleport when the judge tabs back.
- **iOS pitfalls**: Safari has a per-process memory cap (2 GB logged on iOS 26) and crashes rather than warns ([forum](https://discourse.threejs.org/t/memory-limit-crash-on-ios-26/86978)); older iOS leaked memory on every WebGL canvas resize ([WebKit bug](https://bugs.webkit.org/show_bug.cgi?id=219780)). Cap pixel ratio at 1.5 on phones and avoid resize loops. Also, a `wheel`-only scroll handler does nothing on touch; drive from real page scroll or add touch handling.

## 5. How hackathon-grade three.js entries get shipped and judged

- **Hosting with zero build**: GitHub Pages "Deploy from a branch", root or `/docs` folder, republishes on every push ([GitHub docs](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)). Your repo already does this (commit "Drop the Pages workflow, deploy from the branch instead"). Vercel works the same for static folders.
- **What judges see first**: whether the entry meets the stated requirements, then the demo video, which "gives the most amount of scope" and signals effort; one Google judge prefers to play the project and uses the video only when confused ([Devpost judges](https://info.devpost.com/blog/hackathon-judging-tips)). MLH recommends 2-minute videos that demo rather than present ([MLH guide](https://guide.mlh.io/general-information/judging-and-submissions/judging-plan)).
- **Deal-breakers**: ambiguity in the README, polished interface over thin code, recycled projects ([Devpost](https://info.devpost.com/blog/hackathon-judging-tips)).
- **Claude Code hackathon precedent**: the Opus 4.7 hackathon winners shared domain knowledge and real problems; the 3D winner (Virtual Puppet Theater) ran three.js at 60 fps in the browser ([Anthropic blog](https://claude.com/blog/meet-the-winners-of-built-with-opus-4-7-claude-code-hackathon)). No published rubric for a "Build Day" was found; the search surfaced only Code w/ Claude conference pages.
- **What breaks on a judge's laptop**: double-clicked `index.html` runs classic scripts but blocks ES module imports and any file load under `file://` ([WHATWG issue](https://github.com/whatwg/html/issues/8121), [three.js forum](https://discourse.threejs.org/t/cors-multiple-file-project/42073)). Your design (UMD, canvas textures, no files) is exactly the shape that survives this. Other common failures: integrated GPUs at 3× pixel ratio, hidden-tab time jumps, wheel-only scrolling on a trackpad-less touch laptop.

Recommendation: do 1 to 6, in that order, roughly ten hours. Items 7 and 8 are CJ's call; neither is needed to win on the first six, and 8 is only worth it if a post-process look (pencil, pixel, screen-space AO) becomes the art direction.
